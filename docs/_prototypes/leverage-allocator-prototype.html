ImportantPhase 0 prototype – NOT for merge

This page is a throwaway design artifact for dashboard-output-first Phase 0, steps 1 and 4, covering issue #626 (the leverage allocator). It reads the live targets store read-only – no new pipeline target is created, tar_make() is never called, and it is not wired into _quarto.yml. It replicates the allocator arithmetic already shipped as compute_vol_per_unit_gross() / compute_budget_neutral_sigma() in R/plan_leverage.R (landed today via #826) against the real leaderboard target, so every number below is current, not a hand-typed stub. Production implementation waits for explicit approval (Class C gate per human-in-the-loop-decision-points) and, once approved, belongs in leaderboard.qmd (exposure columns) and falsification.qmd (leverage diagnostics) – see “Step 2 – home” below, which is the placement #626’s own issue body already specifies.

Extends the existing causal-DAG surface in falsification.qmd (the “Strategy & Dashboard Relationship Map” tab, itself a #481/#514 seed diagram, rendered via docs/causal-diagrams.js’s dag-portcons-mount) rather than starting a new standalone diagram. This is the missing branch: how a per-strategy volatility target and a gross-exposure convention become an allocated leverage figure, and where that figure meets the still-open backstop decision.

Every node link is pinned to commit de4a4e9 (the #826 merge that landed R/plan_leverage.R) with a #L<n> line anchor per mermaid-click-anchors. Known limitation of this prototype (same as the #735 prototype before it): Quarto’s native {mermaid} fenced block runs mermaid.js in an iframe whose click-through and hover-tooltip behaviour is less reliable than the project’s own causal-diagrams.js mount system – docs/MERMAID_LESSONS.md documents exactly why falsification.qmd moved off native fenced blocks. Production wiring should extend the dag-portcons-mount diagram already in causal-diagrams.js (adding these 6 nodes and their nodeTooltips/edgeMetadata entries) rather than shipping a standalone native block – the diagram above is the design for that extension, not the artifact itself.

Warning
Live allocator arithmetic, this build (commit de4a4e9): budget-neutral sigma_target = 0.1369 (15 strategies with a measurable gross_convention). Implied G_i ranges from 0.73x to 6.61x. A p90-based backstop candidate sits at 1.80x, which binds 2 strategies today (by construction, ~10%). This is materially LOWER than the 3.5x candidate #626’s 2026-08-05 comment derived by hand: that derivation predates the #717/#722 CMR vol-annualisation fixes, which moved CMR’s implied G_i from a stale 4.56x down to a live 0.93x – the exact kind of drift R/plan_leverage.R’s header comment (four prior hand-derivations, three invalidated by data bugs) exists to stop. Today the only strategy near any plausible backstop is Managed Futures (6.61x), and it is an is_cap row – exactly the “measurement artefact” #626’s own comment thread already flagged as inflating its apparent G_i (a 3.0x ceiling it rarely reaches, so its true vol-per-unit-realised-gross is understated). No new dashboard. #626’s own issue body already states the placement: “exposure columns extend leaderboard.qmd; leverage diagnostics extend falsification.qmd.” This prototype’s two artifacts map directly onto that split:

  • The allocator table (Implied G_i, G_i @ backstop, Backstop binds?) belongs in docs/leaderboard.qmd, immediately beside the existing Gross column (same table, same row per strategy) – not a new tab, an extension of the existing exposure disclosure.
  • The regime stress-ratio table and the relationship diagram belong in docs/falsification.qmd’s existing “Strategy & Dashboard Relationship Map” tab (#L901) and its dag-portcons-mount diagram, alongside the covariance-estimator subsystem already documented there.

This output sits beside, and must stay consistent with:

  • Gross column (docs/leaderboard.qmd #L373-377) – same strategy_gross_convention source, same trailing * convention for is_cap ceiling rows. Implied G_i is deliberately placed as a SEPARATE proposed column, not a replacement, because Gross reports what a strategy’s own code implements today and Implied G_i reports what the vol-normalised allocator would assign – conflating them would erase the gap the whole allocator design exists to close.
  • gross_note dynamic disclosure (same file, #L512-523) – this prototype’s summary callout follows the identical pattern: every number computed from the live store, never hardcoded, with the same * convention explained inline.
  • Strategy naming (strategy-name-consistency): strategy values are used unchanged from leaderboard/strategy_gross_convention – no new naming introduced.
  • Captions (visualization-standards family): both table captions are assembled from live values (sigma_target, counts, coverage), matching the project’s established caption style, with source links to R/plan_leverage.R and R/plan_exposure.R.
  • falsification.qmd’s covariance-regularisation block (#L410-468) – named in docs/DASHBOARDS.md’s Template Recipe as the model for a walk-forward-estimator-style diagnostic; the regime stress-ratio table above follows its “comprehensive table + explicit coverage-gap disclosure” shape rather than hiding the #648 gap.
Proposal: fold Implied G_i into the existing Gross column’s cell as a secondary figure, rather than adding it as a wholly separate column.

docs/leaderboard.qmd already carries 21 columns in its main ranking table (Strategy through Breach Risk). Adding Implied G_i, G_i @ backstop, and Backstop binds? as three more columns repeats the “column 60 of 61” sprawl pattern #726 already diagnosed and #735’s prototype already proposed fixing for Rigour. Once the backstop level is actually decided (this prototype’s live numbers argue for something much closer to the p90 ≈ 1.8x than the stale 3.5x), the concrete proposal is:

  • One new column, Gross (target), showing Implied G_i alongside the existing Gross (now relabelled Gross (now)), with the backstop-bound state as a hover tooltip on that cell (same badge pattern as Detection/Rigour) rather than three separate columns.
  • The regime stress-ratio table does not need its own dashboard tab – it folds into the same falsification.qmd tab that already documents the covariance-estimator subsystem, as one more diagnostic accordion, per the Template Recipe.

Net effect on docs/DASHBOARDS.md inventory: dashboard count unchanged (11). Within leaderboard.qmd, net column count grows by one (not three) relative to a naive per-metric-per-column implementation. This is a smaller consolidation than a dashboard merge, but “no change” would understate what this prototype’s own comparable-output audit found: three raw columns compress to one badge column, the same simplification #735 already identified for Rigour/Detection and shipped in #741.
