BDBB Queueing Diagnostics — SOL/USD (Phase 1)

M/G/infinity queueing model (Varma 2026) applied to SOL/USD Kraken hourly data. Replicates resilience half-life estimation and tail-risk predictivity test.

Published

November 4, 2026

Overview

This vignette replicates Varma (2026)’s M/G/∞ queueing model on SOL/USD using Kraken hourly OHLCVT bars. The model characterises the market’s resilience — its tendency to absorb order-flow shocks and revert to equilibrium price — as a queueing process. Three outputs are tracked:

  1. R-metric: variance per unit of signed order flow (volume × direction). Higher R implies prices move more per unit of flow — thinner liquidity.
  2. θ (theta): mean-reversion rate estimated from ACF decay of signed log-returns. Positive θ → mean reversion; negative → momentum.
  3. Half-life: log(2) / θ in hours — the time for half the price impact of a shock to dissipate.

Tail-Risk Predictivity (R vs Amihud vs Kyle)

Note

Methodology fix (2026-09, #868): earlier renders of this page reported a spurious “predictivity” spread. The join scored the SAME bar the rolling window own diagnostics (R, theta, Kyle) were computed from – a contemporaneous, not predictive, association – and the extreme-move threshold was computed over the FULL sample, including bars after each window. Both are look-ahead violations; see bdbb_tail_predict() for the fix. The table below reflects the corrected, next-bar, trailing-threshold test as of the last render of this page – check the build-info footer commit date against the fix merge date if in doubt.

tp <- tar_read(bdbb_sol_tail_predict)
pull_spread <- function(pred) {
  round(dplyr::filter(tp, predictor == pred)$spread_pp, 2)
}
