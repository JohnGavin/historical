# Project Configuration — historical

## Tooling reminders

**API doc regen:** when `packages/historicaldata/R/*` exports change, run `scripts/regen_api_context.sh` before committing. The deployed link from `docs/index.qmd` → `docs/api-historicaldata.md` depends on it. The "functions" stat on the landing page is counted dynamically from `kind: function` lines in that file.

**Automation (issue #438):** A project-local Stop hook (`.claude/hooks/pkgctx_regen_on_stop.sh`) runs automatically at session end. If `packages/historicaldata/R/` was touched during the session it invokes `scripts/regen_api_context.sh`; otherwise it exits silently. The hook is fail-open — a regen failure prints a warning but never blocks the session. A CI check (`.github/workflows/pkgctx-check.yml`) catches any stale doc on PRs that touch `packages/historicaldata/R/` or `docs/api-historicaldata.md`.

**`macro_daily`/`equity_daily` are archived, not stale-pending-refresh (#619, #655, #673):** both HuggingFace-backed datasets read by `hd_macro()`/`hd_ohlcv()` were seeded once (2026-05-06) by duplicating `dsfefvx/finance-historical-data`, which was itself already inactive by then and has had no commits since 2026-04-23. No replacement source is currently being sourced — this is a decision, not an open outage. See [`docs/DATA_SOURCING_LESSONS.md`](../docs/DATA_SOURCING_LESSONS.md) for the full retrospective (what happened, what was tried, lessons for next time) before touching any code that reasons about these datasets' staleness or the Validation-seal boundary (`R/plan_partitions.R`, `R/plan_risk_state.R`).

## Verifying a change (issue #569)

**Run `scripts/verify.sh` — it is the one command to run before claiming a change is verified.** `scripts/verify.sh --quick` does a fast parse-only check; plain `scripts/verify.sh` runs the full suite. Do not hand-roll a verification sequence — every fact below was learned the slow way by agents that got it wrong.

**What `scripts/verify.sh` actually covers, and what it does not (#680):** it runs `parse("_targets.R")`, `parse("docs/_targets.R")`, `tar_validate(script = "docs/_targets.R")`, and the two testthat suites (root + package) — see the table rows below for the full detail on what each covers and, critically, what it still misses. It does **not** build the targets DAG, and a full pass does **not** establish that `tar_make()` still succeeds. Necessary, not sufficient: keep using it as the standard gate, but if a change could plausibly break a target (new/changed upstream dependency, changed column name, new NA-producing path), say so explicitly and run `scripts/build.sh` (main checkout only) to actually build and check the real pipeline.

**`scripts/verify.sh` and `scripts/build.sh` are NOT substitutes for each other (#693).** `verify.sh` runs no target body — it only proves the pipeline parses and is structurally valid, plus the two testthat suites. `build.sh` runs no test — it only proves the last real `tar_make()` left no errored targets. A change needs both: `verify.sh` from any worktree, `build.sh` from the main checkout only (a worktree has no targets store and must not build one that could race the main checkout's `docs/_targets` store).

| Fact | Detail |
|------|--------|
| Build system | This project uses **`flake.nix`**, not `default.nix`. Most global tooling assumes `default.nix` — it does not apply here. |
| Getting R | There is **no R on the bare PATH** (`$IN_NIX_SHELL` is unset in a normal session). Always `nix develop <repo-root> --command Rscript -e '...'`. |
| Shell entry cost | **Warm ~13s. Cold build 10+ minutes** (compiles dozens of R packages). Run verification in the background and wait for it — do not sit blocked on a cold build, and do not report "waiting on the build" as a result. |
| Root test suite | `testthat::test_local()` **fails at repo root** (`Could not find a root 'DESCRIPTION' file`) — the package lives at `packages/historicaldata/`. Use `testthat::test_dir("tests/testthat")` for the root suite instead. |
| Root suite baseline | **3 pre-existing failures** as of 2026-07-19: `test-crypto-momentum.R:51`, `test-qa-summary-deps.R:196`, `test-stock-backtest.R:161`. Not regressions — an agent unaware of this will misread them as its own breakage. `scripts/verify.sh` compares against this baseline by exact signature and only fails on a *different* set. |
| Snapshot tests need `NOT_CRAN=true` | Plain `Rscript -e 'testthat::test_dir(...)'` leaves `NOT_CRAN` **unset**, so every `skip_on_cran()`-gated test — including this repo's mandated snapshot tests (`snapshot-test-policy` rule: error messages, captions, function signatures, target schemas) — is silently skipped and never executed. Confirmed empirically 2026-07-19 on the unmodified root suite: `NOT_CRAN` unset → `failed=3 skipped=41 passed=746`; `NOT_CRAN=true` → `failed=3 skipped=0 passed=800` (same 3 baseline failures either way). `scripts/verify.sh` sets `NOT_CRAN=true` before running either suite and prints the SKIP count in its summary. |
| Pipeline check | `parse("_targets.R")` MUST succeed before every commit (global rule). `scripts/verify.sh` runs this first, always. There are **two** `_targets.R` files, and only one of them is the real pipeline — see the next two rows. |
| Two pipelines, not one (#680) | Root `_targets.R` (~4 `plan_` references) is a small "rn node" sandbox pipeline. `docs/_targets.R` (~148 `plan_` references) is the real one — it produces `leaderboard` and everything this repo publishes. Which one `targets` uses by default is decided by `docs/_targets.yaml`, and that file is **gitignored** — present only in the main checkout, absent in every worktree. Anything that validates the pipeline without passing `script = "docs/_targets.R"` explicitly silently falls back to the sandbox pipeline in a worktree. `scripts/verify.sh` now parses and `tar_validate()`s `docs/_targets.R` directly, always naming `script =`, for exactly this reason. |
| `scripts/verify.sh` validates pipeline STRUCTURE, not BUILD success (#680) | `verify.sh` runs `parse("docs/_targets.R")` plus `tar_validate(script = "docs/_targets.R", store = tempfile())` (no store needed, ~7s warm, safe in a worktree) — this catches malformed pipelines, duplicate target names, circular dependencies, and unresolvable symbols. It does **not** run any target body, so it would **not** have caught either failure that broke `main` this week: PR #678 (a runtime `cli_abort()` inside `ltr_portfolio`, rf coverage) or PR #683 (the same class, `stk_rf` scoped to one consumer's window) — both are structurally valid pipelines that abort on real data. Catching that class needs an actual `tar_make()` plus `tar_meta(fields = error)` against a real store — run `scripts/build.sh`, in the main checkout (a worktree has no store, and must not build one that could race the main checkout's store). `docs/_targets.R` also sets `error = "continue"` project-wide, so `tar_make()` itself exits 0 with errored targets — the exit code cannot be trusted; `build.sh`'s second step, `check_pipeline_errors.R`, reads `tar_meta()` directly instead. A **third**, still-uncovered surface: `docs/*.qmd` chunks call `tar_read()` for a specific target name, and a chunk referencing a target that no longer exists (typo, rename, removal) fails only at **render** time — not at parse, not at `tar_validate()`, not at `tar_make()`. Nothing in the repo automates a render-time check yet; treat any PR touching `docs/*.qmd` `tar_read()` chunks as needing a manual render before merge. |
| `scripts/build.sh` — build the real pipeline and prove it, in one command (#693) | Before this, `tar_make()` and `scripts/check_pipeline_errors.R` were two commands, and only the first was habitual — #691 (six registry writers erroring on every build for four commits) was found on the first occasion anyone ran the second by hand. `scripts/build.sh` runs `tar_make(script = "docs/_targets.R", store = "docs/_targets")` then runs `check_pipeline_errors.R` **unconditionally**, including when `tar_make()` itself exited non-zero — a crashed build still leaves errored targets worth naming. Refuses to run outside the main checkout (`git rev-parse --absolute-git-dir` containing `/.git/worktrees/` means a linked worktree — exit 2). Exit codes: `0` clean build, `1` build ran but reported a problem (errored targets and/or a non-zero `tar_make()` exit), `2` did not run at all (wrong location, nix shell unusable, or no store to check). Takes 40+ minutes on a cold pipeline; not part of CI (see the next row) — run it locally after any change that could plausibly break a target body. |
| A change under `packages/*/R/` needs `scripts/build.sh`, not just `scripts/verify.sh` (#753) | `pkgload::load_all()` (`docs/_targets.R:25`) is how `historicaldata` gets loaded, and functions arriving that way are **not** tracked as target dependencies the way root `R/plan_*.R` sourced functions are — `tar_make()` silently **skips** a target whose called function changed, `build.sh` used to report `PASS`, and `tar_read()` served the previous version's value. Reproduced on PR #752 (a CMR lookback-window fix that `tar_make()` skipped rebuilding twice in a row). Fixed in three parts, none of which is `verify.sh` (it runs no target body, so it cannot see this at all): (1) `tar_option_set(imports = "historicaldata")` in `docs/_targets.R` auto-tracks every **bare-name** package call (`hd_fn()` — confirmed empirically, this is exactly PR #752's call shape) with zero per-target edits, but **not** `historicaldata::fn()` **namespaced** calls (`targets`' own documented limitation of `codetools::findGlobals()` — confirmed empirically the same way; 22 files / ~135 lines in this repo's `R/` use that form); (2) `pkg_source_files`/`pkg_source_digest` targets (`docs/_targets.R`) give any target an explicit, file-hash-tracked dependency to opt into by referencing `pkg_source_digest` in its own command; (3) `scripts/check_pkg_staleness.R`, run **unconditionally** as `build.sh` Step 2c, is the backstop — it discovers every target defined in a file that mentions `historicaldata::` and fails the build (`[STALE-PKG]`) if any of them was **skipped** in a run where the package source changed. This could **not** be a `tar_target()` gate in `R/plan_qa_gates.R` (see its `qa_pkg_source_tracked`, S22, for the narrower check that *can* live there) — `tar_meta()`/`tar_progress()` are unsupported against the store of the pipeline currently running, confirmed empirically. **Still true after this fix:** `verify.sh` alone remains insufficient for a `packages/*/R/` change — only `build.sh`'s Step 2c actually proves nothing was left stale. |
| `scripts/build.sh --render` — close the loop between detecting and republishing stale dashboards (#695) | `scripts/check_dashboard_freshness.R` (run unconditionally as Step 3 of `build.sh`) only *detects* pages whose `.qmd` or upstream data is newer than the committed `.html` — nothing re-renders them, so GitHub Pages keeps serving the stale copy until a human remembers to `quarto render` by hand. `--render` closes that gap: after a clean build (`tar_make()` exit 0 **and** no errored targets — staleness itself does not gate this), it parses Step 3's own `[STALE]`/`[DATA-STALE]` output for exactly which pages need it and renders each one individually via its own `quarto render` call, so one broken page (e.g. #699) can't hide a pass on the rest. Every rendered page is then grepped for the same five error patterns the Post-Deploy Validation table above checks against the live site. It never commits or pushes — rendered files are left in the working tree for review. Exit `3` (new) means the build was clean but one or more renders failed; distinct from exit `1` (a build problem). Main checkout only, same as plain `build.sh`. |
| CI coverage gap | `r-tests`/`pkgctx` CI only fire on `packages/historicaldata/**`. Changes to root `R/`, `scripts/`, and `tests/` get **no CI at all** — local `scripts/verify.sh` is the only gate for those paths, and neither it nor any CI workflow ever runs `scripts/build.sh` (a 40+ minute build against live data endpoints is a separate and much larger decision — see #673, #693). |
| History: `scripts/verify.sh` used to check the wrong, near-empty pipeline (#680) | Before this was fixed, `verify.sh` ran `parse("_targets.R")` against the ROOT pipeline only — a ~4-`plan_`-reference sandbox, not the ~148-reference `docs/_targets.R` that actually builds `leaderboard`. PR #678 passed `verify.sh` completely (root 468/3/0, package 694/1/15, baselines exact) and left `main` with 4 errored targets, including `leaderboard`, because nothing verify.sh ran ever touched the real pipeline. Fixed by adding the `parse()` + `tar_validate()` checks against `docs/_targets.R` described in the row above — but read that row's limits carefully: structural validation is still not build verification. |
| testthat edition 3 — how it is actually set (#578/#579) | The repo root is **not** a package, so testthat's `find_edition()` finds no `DESCRIPTION` and returns **edition 2**. A `tests/setup.R` **cannot** fix this: `edition_get()` caches into `the$edition` before setup runs. Measured — `local_edition(3, .env = teardown_env())` → 2 (this is what the global rule prescribes; see [llm#799](https://github.com/JohnGavin/llm/issues/799)), `.env = globalenv()` → 2, `options(testthat.edition = 3)` → 2, `Sys.setenv(TESTTHAT_EDITION=3)` inside setup.R → 2. Only `TESTTHAT_EDITION=3` exported **before** `test_dir()` works → 3. `scripts/verify.sh` exports it and asserts the active edition is 3, exiting 2 if not. |
| New root test files MUST declare `local_edition(3)` | The env var only applies when tests run **via `scripts/verify.sh`**. Anyone invoking `testthat::test_dir()` directly gets edition 2, under which `expect_snapshot()` and `expect_warning()` behave differently. So keep `testthat::local_edition(3)` at the top of every root test file — the 29 existing declarations are **load-bearing, not redundant boilerplate**. Deleting them is how #574 (54 silently-skipped tests) comes back. Concrete precedent: `test-stock-backtest.R` had `result <- expect_warning(f(...))`, which under edition 3 returns the *condition object*, not the value — `result$capped_w` was `NULL` and `sum(NULL)` masked the assertion (fixed in #581). |
| 7 tests are **integration tests**, not unit tests (#580) | `test-query.R` (×5), `test-ranked.R`, and `test-registry.R` guard themselves with `skip_if_no_remote_data()` (`packages/historicaldata/tests/testthat/helper-skip.R`) because they hit a **live `hf://` parquet endpoint**, not a local fixture. Beyond `skip_on_cran()`/`skip_on_ci()`/`skip_if_offline()`, the guard runs a cheap real probe (`LIMIT 1` read, memoised per session) and `skip()`s — with the underlying error named in the message — when the endpoint is reachable but not serving valid data (rate-limited/truncated/erroring). This stops `duckdb_error: TProtocolException: Invalid data` from corrupting the package-suite baseline in `scripts/verify.sh` (observed twice on clean `main`, hours apart, no code change). **A rising SKIP count is lost coverage, not success** — `scripts/verify.sh` documents the normal package-suite skip count (15, updated 2026-07-22 under #580 Phase 2: 4 from `{alphavantager}` not installed + 11 from `test-remote-live.R`'s opt-in live-endpoint coverage gated on `HD_TEST_LIVE`) next to the failure baselines and, since #654, **fails the run** (not just prints) whenever the package-suite count exceeds it, showing *which* tests skipped and *why*. Do not raise that baseline number to silence a real outage; investigate instead. |
| AlphaVantage tests are correctly-skipped, not dead code (#654) | `{alphavantager}` is deliberately **not** in the nix environment: it is declared under `Suggests:` in `packages/historicaldata/DESCRIPTION` (not `Imports:`), `hd_alphavantage()` gates on it via `rlang::check_installed()`, and the 4 tests that need it (`test-alphavantage.R` ×3, `test-column-naming.R` ×1) correctly use `skip_if_not_installed("alphavantager")` — 2 other `test-alphavantage.R` tests (`hd_av_registry` structure/schema) carry no such guard and always run. This is the standard CRAN pattern for an optional, credentialed, rate-limited (5 req/min, 500/day) external API that must never be called from CI on every push — see the roxygen `@section CI safety` in `R/alphavantage.R`. **Verdict: keep as-is.** Do not add `{alphavantager}` to the nix environment (it would force a paid/keyed dependency on every contributor for one opt-in data source) and do not delete the tests/code (the function is exported, documented, registered in `hd_av_registry()`/`registry.R`, and column-naming behaviour it guards — `adjusted_close`, #325 — is real). Confirmed empirically 2026-08-05: `scripts/verify.sh`'s 15 skips are exactly 4 (`{alphavantager}` absent) + 11 (`test-remote-live.R`, `HD_TEST_LIVE`-gated) — no unexplained residue. |
